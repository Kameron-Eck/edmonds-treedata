## Thread 1: 4-band imagery → RGB-only (crash fix)

**The bug:** `2016_snoh_rgbi.tif` etc. are RGB+NIR (4 bands). The coarse
city-wide tiling path read ALL bands (`src.read(window=...)`) into a (4,512,512)
array and wrote it into a `count=3` GeoTIFF profile → `ValueError: Source shape
(4,512,512) is inconsistent with given indexes 3` at `step_tile`. Every `_rgbi`
year (all coarse) failed to tile.

**Fix (v024):** the city-wide read now uses `src.read([1,2,3], ...)` — drops NIR,
matching `read_rgb_window`. The negative-site and 6-site paths already read
`[1,2,3]`, so this one line is the whole fix. The 4 RGBI years now tile + train
as 3-channel RGB against the Phase-3 RGB checkpoint (no inflation, no special
casing). `.versions/v024_2026-06-29_drop_nir_rgb_only_crashfix.py`.

**History note:** v023 (`nir_4th_band_per_year_4channel_rgbi`) implemented a full
per-year RGB+NIR model with conv-1 inflation. Kam decided to drop NIR before it
was run on Colab. It's in `.versions/` — restore it only if NIR is revisited.

**Open follow-up:** none for this thread. RGBI years are now first-class RGB.

## Thread 2: County LIDAR hillshade — downloaded + staged

**File:** `Full_Image/Pipeline Imagery/lidar_snoh_hillshade_fr.tif`
- Source: `gis.snoco.org/.../LIDAR_HILLSHADE_FIRST_RETURN/ImageServer` — a
  first-return (DSM) hillshade = canopy/building tops (structure signal that
  separates trees from grass; a bare-earth model would not).
- **EPSG:3857, 1 m/px, single band U8 0–254, 11441×16052 px, ~117 MB.**
- Clipped to the **union extent of all 19 orthos** (11.44 × 16.05 km). Verified:
  every ortho footprint is fully inside the hillshade. ~57% fill over most
  orthos is Puget Sound water + out-of-city area in the bbox (land-centered Snoh
  years show ~75%); zeros are no-first-return, not missing data.
- Built by tiling exportImage into 6 full-width horizontal strips (each under the
  15000×4100 export cap), georeferencing each from its known request bbox (not
  trusting server geotags), then `rasterio.merge`. Fetch script:
  `scratchpad/fetch_lidar.py` (local one-off; uses locally-pip-installed
  rasterio+requests — NOT on Drive, regenerate from the handoff if needed).

**WIRED IN as a 4th input channel — v025 (compiles + tested, not yet run on Colab).**
- `--hillshade` (default ON) / `--no-hillshade`. Uniform across all 18 years (one
  ~2016 snapshot), so the model is a clean 4-channel RGB+hillshade — none of the
  per-year-variable mess that sank NIR.
- **Single injection point:** `step_tile` reprojects the hillshade onto each
  tile's native grid (`read_hillshade_chip`, EPSG:3857→tile CRS, bilinear) and
  bakes it as band 4 at write time. Every record carries crs+tile_transform, so
  all tiling modes (city-wide / 6-site / negative) get it for free; the tiling
  functions themselves were not touched. Site crops stay 3-band RGB — hillshade
  is added only at the final tile write.
- Model auto-matches the tiles: `step_train`/`step_evaluate` set IN_CHANNELS from
  the tile band count; `_save_ckpt` records `in_channels`; `step_inference` reads
  it back and reprojects the hillshade per window. Phase-3 (3ch) is inflated 3→4
  with the new conv-1 channel **zero-init** (`_inflate_first_conv`) so pretrained
  RGB is preserved and hillshade is learned. No flag/tile mismatch possible:
  3-band tiles → 3ch model, 4-band tiles → 4ch model, regardless of the flag.
- HS normalization stats (measured from the raster, /255 nonzero): **mean 0.58,
  std 0.26**. 4ch input routes through the numpy normalizer (`rgb_to_model_input`)
  not albumentations; spatial aug joint, colour aug on RGB only (hillshade passed
  through). Same proven pattern as the VI path.
- **Validated locally** (rasterio + real data): reprojection co-registers across
  CRS/GSD (2285@50cm, 3857@7.5cm, 90-100% land coverage, real relief); 4-band
  tile write→read round-trip preserves the hillshade in band 4; numpy logic test
  confirms channel order [R,G,B,HS], HS stats, and zero-init inflation. Untested:
  the torch training loop / albumentations on 4ch arrays (Colab smoke test).
- **SMOKE TEST (Colab):** `%run phase4_semantic_finetune.py --year 2016 --step tile`
  (expect "+ LIDAR hillshade band 4" + 4-band tiles) → `--step train` (expect
  "Input channels: 4 (RGB+hillshade)" + the "inflated input conv ... zero-init"
  line). Compare a year with vs `--no-hillshade` for the ablation.
- Re-tiling + re-training is required to (de)activate — the flag only changes what
  `--step tile` bakes; existing 3-band tiles are untouched until re-tiled.

**Older note (superseded):** the v023 NIR machinery was the template; this reuses
its normalization/inflation/augmentation patterns but the 4th channel is an
external co-registered raster, uniform across years (simpler).
- **Acquisition date (found):** the hillshade derives from the **USGS/WADNR
  "Western Washington 3DEP" QL1 LiDAR** (8 pts/m²), flown **March 2016 – June
  2017, predominantly 2016** (Quantum Spatial technical report signed 2017-09-29,
  field work 3/17/2016–6/19/2017; hillshade generated 2018-05-01). The service's
  one-line abstract loosely says "2013–16" but that's stale — the linked
  technical report (Western_Washington_3DEP_Technical_Data_Report.pdf) is the
  authority. Exact Edmonds flight day is only in the Figure 2 acquisition map.
- **Temporal-leakage caveat:** single ~2016 snapshot. Best match for the 2015/
  2016/2017 imagery; mostly fine for 2019–2024 (mature canopy stable); highest
  drift risk for 2000–2012 (trees grown/planted/removed, development) — weight/
  limit its use for those distant years if it's ever wired in as a model input.
- Also available on that server if needed: `LIDAR_HILLSHADE_BARE_EARTH` and a real
  F32 `Topography/Elevation` grid (true nDSM = first-return − bare-earth is not
  directly served).
